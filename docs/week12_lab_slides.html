Part 2 · 0:08–0:20

The Tools Describe Themselves

Teaching goal: a tool is an ordinary method; its docstring is now read by a program.

The model asks; your code decides

Concept

The chatbot sends a list of tools along with the conversation.

The model writes a reply, or sends a tool call: a name and the values to use.

It never runs anything. Your code decides whether to run the tool.

A decision is a dictionary: {"text": ...} or {"tool": ..., "arguments": {...}}.

Stress the second bullet. Students often believe the model executes their code.

Tell the two shapes apart

decision = {"tool": "look_up_order", "arguments": {"order_id": "A101"}} print("text" in decision) print(decision["tool"], decision["arguments"]["order_id"])

No model here. "text" in decision asks whether the dictionary has that key. Press Run.

The chatbot uses exactly this test to decide whether it got a reply or a tool request.

Expected output

False
look_up_order A101

False: this decision is a tool request, not a reply.

Ask: what would the dictionary look like if the model just wanted to say hello?

order_tool.py — the method the model may ask for

def look_up_order(self, order_id): """Look up the status of one order. Args: order_id: The order ID, like A100. """ found = self.find_order_id(order_id) if found is None: return "No order with that ID was found. Order IDs look like A100." return f"Order {found} is {self.find_status(found)}."

The docstring's first line says what the tool does; Args: says what each value looks like.

Orders are now dictionaries with a status and an address. Point at find_order_id: last week's method, so a100 still works.

Check it in the Python shell

Changes Wait for a Person

Teaching goal: a change tool files a request; only an approval changes data, and only once.

A request waits; an approval changes the order

orders = {"A100": {"status": "shipped", "address": "14 Bay Road"}} requests = [] request = {"number": 1, "order_id": "A100", "new_address": "9 Pine Street"} request["status"] = "waiting" requests.append(request) print(orders["A100"]["address"], request["status"]) if request["status"] == "waiting": request["status"] = "approved" orders[request["order_id"]]["address"] = request["new_address"] print(orders["A100"]["address"], request["status"])

Plain dictionaries and a list, no classes. ChangeQueue wraps exactly this. Press Run.

Return to the opening question: the chatbot never changes the address. It files a request, and a person decides.

Expected output

14 Bay Road waiting
9 Pine Street approved

The address changes only after the status moves from waiting to approved.

Ask: what stops this from running twice? The status check.

change_queue.py — approve is the only code that changes an order

def approve(self, number): """Approve one waiting request and make the change.""" request = self.find(number) if request is None: return f"There is no request {number}." if request["status"] != "waiting": return f"Request {number} is already {request['status']}." request["status"] = "approved" self.order_tool.change_address(request["order_id"], request["new_address"]) return f"Request {number} approved."

A request that is already approved or rejected is refused, so a change can never happen twice.

Students type the whole change_queue.py from the lab page, then run the shell check there.

One Door for Every Tool

Teaching goal: every request passes Toolbox.run, which refuses unknown tools, empty values and made-up details.

toolbox.py — run

def run(self, name, arguments, history): """Check one tool request. Run the tool only if every check passes.""" if name == "look_up_order": order_id = self.clean(arguments, "order_id") if order_id == "": return "The order ID is missing. Ask the customer for it." if not self.customer_said(history, order_id): return "The customer has not given that order ID. Ask them for it." return self.order_tool.look_up_order(order_id) if name == "check_stock": item = self.clean(arguments, "item") if item == "": return "The product is missing. Ask the customer which product." return self.stock_tool.check_stock(item) if name == "request_address_change": order_id = self.clean(arguments, "order_id") new_address = self.clean(arguments, "new_address") if order_id == "" or new_address == "": return "The order ID and the new address are both needed." if not self.customer_said(history, order_id): return "The customer has not given that order ID. Ask them for it." if not self.customer_said(history, new_address): return "The customer has not given that address. Ask them for it." return self.change_queue.request_address_change(order_id, new_address) return f"There is no tool named {name}."

Each refusal is a sentence for the model, which reads it as the tool's result.

Walk one branch out loud: name known, value present, customer said it. Then the tool runs.

Did the customer say it?

def customer_said(history, text): for message in history: if message["role"] == "user" and text.lower() in message["content"].lower(): return True return False history = [{"role": "user", "content": "I want to change my shipping address"}] print(customer_said(history, "A100")) print(customer_said(history, "shipping ADDRESS")) print(customer_said(history, ""))

Part 5 · 0:45–0:58

The Tool Loop

Teaching goal: ask, check, run, record, ask again, at most three times. Then test it with FakeModel.

The loop, with the model's decisions written out

decisions = [ {"tool": "look_up_order", "arguments": {"order_id": "A101"}}, {"text": "Order A101 is still processing."}, ] history = [{"role": "user", "content": "Has my package A101 shipped?"}] reply = None rounds = 0 while reply is None and rounds < 3: decision = decisions[rounds] if "text" in decision: reply = decision["text"] else: print("tool request:", decision["tool"], decision["arguments"]) history.append({"role": "tool", "content": "Order A101 is processing."}) rounds += 1 print("reply:", reply) print("history entries:", len(history))

The while stops when there is a reply or after three rounds. Press Run.

This is model_reply with the model replaced by a list. The chatbot version calls decide and run.

Expected output

tool request: look_up_order {'order_id': 'A101'}
reply: Order A101 is still processing.
history entries: 2

Two trips for one message: a tool request, then the reply. The history gained the tool entry.

Ask what happens if every decision is a tool request: the loop stops after three rounds.

chatbot.py — model_reply

def model_reply(self): """Ask the model. Run each tool it asks for, then ask again, up to a limit.""" rounds = 0 while rounds < MAX_TOOL_ROUNDS: tool_list = self.tools.tool_list() decision = self.model.decide(self.instructions, self.history, tool_list) if decision is None: return "Sorry, I can't answer that right now. Please try again in a moment." if "text" in decision: return decision["text"] name = decision["tool"] arguments = decision["arguments"] result = self.tools.run(name, arguments, self.history) self.history.append( { "role": "tool", "tool_name": name, "arguments": arguments, "content": result, } ) rounds += 1 return "Sorry, I couldn't finish that. I'm passing you to a human agent."

After MAX_TOOL_ROUNDS the customer goes to a person.

The chatbot now takes four values: name, instructions, tools, model. The order and stock rules are gone; the payment rule stays.

Mini-project — let your assistant choose its tool

What to build

One change waits for approval and can only be applied once. One rule still hands something to a person.
