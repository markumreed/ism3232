Section 2

Reruns

The counter that will not count.

⌨ counter.py

# counter.py
import streamlit as st

count = 0
if st.button("Add one"):
    count = count + 1
st.write(f"Count: {count}")

# After 3 clicks the page shows:
# Count: 1
Ask what they expect after three clicks before you show it. Every click reruns the script, so count = 0 runs again.

⌨ counter_state.py

# counter_state.py
import streamlit as st

if "count" not in st.session_state:
    st.session_state.count = 0
if st.button("Add one"):
    st.session_state.count = st.session_state.count + 1
st.write(f"Count: {st.session_state.count}")

# After 3 clicks the page shows:
# Count: 3
st.session_state is the one thing Streamlit keeps between runs. A browser refresh starts a new session: Count: 0.

You have seen this before

  • Week 11: the model remembers nothing, so we send the history every time
  • Streamlit remembers nothing either
  • So the chatbot lives in st.session_state
Connect the two ideas; this is the week's one rule.

Section 4

The Staff Tab

A person decides.

⌨ The waiting requests

    st.subheader("Waiting for approval")
    waiting = waiting_requests(DB_FILE)
    if waiting == []:
        st.write("Nothing is waiting.")
    for request in waiting:
        number = request["number"]
        text_col, approve_col, reject_col = st.columns([4, 1, 1])
        text_col.text(
            f"Request {number}: {request['order_id']} to {request['new_address']}"
        )
        if approve_col.button("Approve", key=f"approve{number}"):
            st.session_state.notice = approve_request(DB_FILE, number)
            st.rerun()
        if reject_col.button("Reject", key=f"reject{number}"):
            st.session_state.notice = reject_request(DB_FILE, number)
            st.rerun()
st.columns makes three columns; key= names each button; the notice goes in session_state because Approve's run ends in st.rerun().
