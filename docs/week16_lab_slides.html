ai_feature.py — the whole file

import anthropic

def summarise_request(category: str, description: str) -> str:
    """
    Return a one-sentence AI summary of a business request.
    Only category and description are sent -- no names, IDs, or amounts.
    """
    client = anthropic.Anthropic()
    prompt = f'Summarise this {category} business request in one clear sentence:\n{description}'
    message = client.messages.create(
        model='claude-haiku-4-5-20251001',
        max_tokens=150,
        messages=[{'role': 'user', 'content': prompt}]
    )
    return message.content[0].text

The bug (guide): Streamlit re-runs the entire script top to bottom on every interaction. Clicking "Generate AI Summary" makes st.button('Generate AI Summary') return True for that one run, and inside that run the whole block executes — including the line that defines the "Looks good" button for the first time. But clicking "Looks good" triggers a new, separate re-run from the top. On that run, st.button('Generate AI Summary') is False, so the entire if block — including the line that defines the "Looks good" button — never runs. The click on a button that, from Streamlit's perspective, no longer exists on this run has nowhere to register. That is why it vanishes and nothing saves. This is the human review gate — Control #2, the most safety-critical of the six. The fix (guide): store the summary in st.session_state (a dict-like object that persists across re-runs for the life of the browser session), and move the if 'ai_summary' in st.session_state: check outside the Generate button's if block, at the same indentation level. After a successful save, del st.session_state['ai_summary'] so the summary and review button do not keep reappearing on future re-runs. Common student mistakes: copying the lab's nested-button version verbatim and testing only "does the summary generate" (which works fine) without testing the save step — the first half of the flow works perfectly, so the bug goes unnoticed. After applying the fix, forgetting the del st.session_state['ai_summary'] cleanup line — a confusing UX where an old summary keeps showing up. Check for understanding: "Why didn't the first required control — the disclosure label — have this same bug, but the second one — human review — did?" (Because the disclosure label (st.info(...)) is defined and shown within the same re-run as clicking 'Generate' — it doesn't need to persist to a different, later re-run the way the review button's click-and-save action does. Anything that needs to survive across two separate user interactions needs st.session_state; anything that only needs to exist within one single interaction's re-run doesn't.)

description = st.text_area('Request description (for AI summary)')

if description:
    if st.button('Generate AI Summary'):
        with st.spinner('Generating summary...'):
            from ai_feature import summarise_request
            st.session_state['ai_summary'] = summarise_request(category, description)

    if 'ai_summary' in st.session_state:
        # Required: disclosure label

        if st.button('Looks good -- save with this summary'):
            add_record(requester, category, amount, notes=st.session_state['ai_summary'])
            st.success('Record saved with AI summary.')
