⚠
Individual work — notes and labs, no AI
You may use your own notes, your own labs and assignments, and the course site. AI tools of any kind are not allowed, including chat assistants and AI code completion in your editor. No help from another person, and no other student's code or repository.
⚠
Loop only
The function that adds up a list of records must get its total from your own for loop. Do not use sum(), max(), min(), sorted(), or comprehensions.
What Is and Is Not Tested
Covered — all course material, Weeks 1–8

Terminal: pwd, ls, cd, mkdir, touch, tree, code .

venv + pip: create, activate, install, freeze

Project files: requirements.txt, .gitignore, README.md

The ritual: ruff format, ruff check, pytest, then commit and push

Git: init, add, commit, push, log, status

Python: constants, operators, conditionals, loops, lists of dictionaries, functions, modules, pytest, tracebacks

The project puts all of it to work in one repository.

NOT tested

❌ OOP (classes, objects, inheritance)

❌ SQL and SQLite

❌ Streamlit

What each part leans on

Functions: every parameter the rule mentions is read · boundary words translated exactly (“or more” is >=, “below” is <) · tiers checked in one order · return, not print · return after the loop, not inside it

Tests: the value exactly at each limit and the value next to it · expected values worked out by hand from the rules · a list built inside the test · names that say what is checked

Project: exact file names · tests/__init__.py · no .venv/ in the repository · output that matches line for line

Workflow: format, then check, then test · a commit each time a part works · a README whose commands actually run

Samples — Format Only
💡
These show the format, not the difficulty
Each sample comes from the purchase-approval rules you know from Lab 7. The exam uses a business you have not seen, and its rules have more parts. The Study Guide works a full example, with seven bugs to find and a practice project at exam size.
Part 2 format — a business rule turned into a function
# Rule: a request of $1,000 or more goes to a director.
# A request of at least $500 goes to a manager, and so does
# any request from a department that is over budget.
# Everything else is approved automatically.
DIRECTOR_LIMIT = 1000.00
MANAGER_LIMIT = 500.00


def get_approver(amount: float, over_budget: bool = False) -> str:
    """Return who must approve a request."""
    if amount >= DIRECTOR_LIMIT:
        return "Director"
    elif amount >= MANAGER_LIMIT or over_budget:
        return "Manager"
    else:
        return "Automatic"
Part 4 format — tests on both sides of a limit
from business_rules import get_approver


def test_director_at_exactly_1000():
    assert get_approver(1000.00) == "Director"


def test_manager_one_cent_below_1000():
    assert get_approver(999.99) == "Manager"


def test_over_budget_small_request_goes_to_manager():
    assert get_approver(300.00, over_budget=True) == "Manager"
Part 6 format — the ritual, then a commit that says what changed
# The ritual: all three must come back clean
ruff format .
ruff check .
pytest -v

# Then a commit whose message says what changed
git add .
git commit -m "Add approver function with boundary tests"
git push
Midterm Logistics — Instructor Checklist
Before the exam opens

☐ Post the Canvas assignment with the project brief. The submission is a text entry: the repository URL.

☐ Set the opening and due dates in Canvas. The window runs about a week.

☐ Remind students the week before: at home, their own notes and labs and the course site, no AI tools, a GitHub URL only.

☐ Have every student push a small change to GitHub from the terminal before the window opens, so login problems surface early.

Grading

☐ Grade from a fresh clone. Run ruff format --check ., ruff check ., pytest -v, and python3 main.py on the clone.

☐ Run the instructor's tests against each student's functions.

☐ Read the function that totals the list. Work done with sum(), max(), min(), sorted(), or a comprehension is not accepted.

☐ Read the Git log for the number of commits, the messages, and the stages.

☐ Only what was pushed by the deadline is graded.

After the exam — looking ahead

Week 10 begins OOP. Students who struggled on the midterm with functions and scope will face additional difficulty with classes and methods. Offer office hours before Week 10 for students who want to consolidate function fundamentals before OOP begins.
