The idea — streamlit run, and "the whole script re-runs"

Concept

streamlit run app.py, not python3 app.py — streamlit run starts a small local web server and opens a browser tab pointed at it (http://localhost:8501 by default). Running the same file with python3 executes without error but renders nothing — st.title() / st.write() need the Streamlit server process to draw anything.

st.title(...) / st.write(...) are not print() — they render formatted HTML elements in the browser, not terminal text.

The one fact that explains everything today

Streamlit re-runs your entire script, top to bottom, every single time you interact with any widget — click a button, change a dropdown, type in a box. It is the whole model, not a bug to work around, and it is why today's code looks the way it does.

The re-run model is the load-bearing idea for the whole lab — every later "why does this work" answer traces back to it. State it now, before any real code, and keep it visible. There is no runnable block here: this is Streamlit-only, so the hello-world file on the next slide is shown static.
