Exam format

The midterm is a take-home project worth 100 points. You get a project brief: one business and its pricing rules, written in plain English. You turn those rules into a small, tested Python project, the same shape as Lab 7, and submit the link to your GitHub repository.

Where
At home
On your own computer, in your own editor and terminal
When
About a week
Opens at the start of Week 9. The exact dates are in Canvas
How long
2 to 3 hours of work
You do not have to finish in one sitting
Submission
A GitHub URL only
Your public repository is the entire submission

Your project brief is in the Canvas assignment. Expect it to go further than Lab 7: the rules have more parts, one function works through a list of records, and you write the tests yourself.

What you build

One new public repository with exactly this structure:

ism3232-midterm/
├── business_rules.py
├── main.py
├── README.md
├── requirements.txt
├── .gitignore
└── tests/
    ├── __init__.py
    └── test_business_rules.py
FileWhat goes in it
business_rules.pyFive functions that carry out the brief's rules. Each has type hints, a docstring, and a return. Every number from the rules is a named constant. No print().
main.pyImports your functions, loops over a list of records given in the brief, and prints a report. Your output must match the brief line for line.
tests/test_business_rules.pyAt least 10 pytest tests that you write, including the value on each side of a limit.
README.mdSix sections: a title block, what the program does, the business rules, how to run it, how to test it, and your AI use statement.
requirements.txt, .gitignoreThe same two files every project has had since Week 3.

Your Git history is part of the exam too. Commit as you finish each part, with at least five commits whose messages say what changed.

⚠ Loop only

One of your functions adds up a list of records. Its total must come from your own for loop. sum(), max(), min(), sorted(), and comprehensions are not accepted.

How the 100 points are earned

CriterionPointsWhat earns them
Complete submission15A public repository with every required file, a main.py that runs and matches the expected output, and functions with type hints, docstrings, and named constants
Functions correct30The instructor's own tests run against your functions. They check ordinary cases and the value on each side of every limit
Tests you wrote20At least 10 passing tests that cover every function, both sides of at least two limits, and a list you build inside a test
ruff10ruff format --check . and ruff check . both come back clean
Commit history15At least five commits with descriptive messages, showing the project built in stages
README.md10All six sections filled in, correct run and test commands, and clean Markdown on GitHub
Total100

Your functions are tested by name, so use the function names and the parameter order exactly as the brief gives them. Thirty points depend on it.

What you may use

✓ You may use

Your own notes · Your own labs and assignments · The course site: readings, lectures, labs, and the Study Guide.

⚠ You may not use

AI tools of any kind, including chat assistants and AI code completion in your editor · Help from another person · Another student's code or repository.

This is an individual exam. Your README ends with a one-sentence AI use statement, the same way your Lab 1 README did.

Before you submit

  • ruff format ., then ruff check ., then pytest -v: all three come back clean
  • python3 main.py prints exactly what the brief shows
  • git status says there is nothing to commit, and git log --oneline shows at least five commits you would be happy for a manager to read
  • The repository is Public. Open its URL in a private browser window: if you cannot see your files without logging in, the grader cannot either
  • The README renders cleanly on GitHub, with no brackets or template text left
  • The URL is pasted into the Canvas text box

Only what is pushed to GitHub by the deadline is graded.

How to prepare

  • Work through the Study Guide, and find each bug before you open the answer
  • Build its practice project from an empty folder to a pushed repository. It has the same six parts as the exam
  • Open your Lab 7 project and run the ritual again. If ruff check . or pytest complains, find out why now
  • Redo any assignment where you lost points
  • Write boundary tests for a function you wrote earlier in the semester
  • Read one traceback from your own code, bottom-up, and explain it aloud
  • Push a small change to GitHub from your terminal before the exam opens, so you know your login still works

After the midterm
