Section 2

Tool Calls

The model asks; your code decides.

The model asks; your code decides

  • The chatbot sends a list of tools with the conversation.
  • The model writes a reply, or sends a tool call: a name and values.
  • It never runs anything. Your code decides whether to run the tool.
  • A decision is a dictionary: {"text": ...} or {"tool": ..., "arguments": {...}}.
Stress that the model cannot run code. Everything that happens is done by your program.

⌨ order_tool.py — a method the model may ask for

    def look_up_order(self, order_id):
        """Look up the status of one order.

        Args:
            order_id: The order ID, like A100.
        """
        found = self.find_order_id(order_id)
        if found is None:
            return "No order with that ID was found. Order IDs look like A100."
        return f"Order {found} is {self.find_status(found)}."
The docstring's first line says what the tool does. Args says what each value looks like. The ollama package reads both. Until today a docstring was for people; now a program reads it.
Section 3

The Tool Loop

One message can take two trips to the model: ask for a tool, then answer.

⌨ ollama_model.py — the new method, decide

    def decide(self, instructions, history, tools):
        """Send the conversation and the tools. Return a reply or a tool request."""
        messages = [{"role": "system", "content": instructions}]
        for message in history:
            if message["role"] == "tool":
                messages = messages + self.tool_messages(message)
            else:
                messages.append(message)
        try:
            response = chat(model=self.model_name, messages=messages, tools=tools)
        except ConnectionError:
            return None
        except ResponseError:
            return None
        if response.message.tool_calls:
            call = response.message.tool_calls[0]
            return {"tool": call.function.name, "arguments": call.function.arguments}
        return {"text": response.message.content}
decide sits beside reply. reply stays because the Week 11 mini-project still uses it. tool_calls[0]: this chatbot runs the first request and lets the model ask again.

⌨ chatbot.py — model_reply, write together

    def model_reply(self):
        """Ask the model. Run each tool it asks for, then ask again, up to a limit."""
        rounds = 0
        while rounds < MAX_TOOL_ROUNDS:
            tool_list = self.tools.tool_list()
            decision = self.model.decide(self.instructions, self.history, tool_list)
            if decision is None:
                return "Sorry, I can't answer that right now. Please try again in a moment."
            if "text" in decision:
                return decision["text"]
            name = decision["tool"]
            arguments = decision["arguments"]
            result = self.tools.run(name, arguments, self.history)
            self.history.append(
                {
                    "role": "tool",
                    "tool_name": name,
                    "arguments": arguments,
                    "content": result,
                }
            )
            rounds += 1
        return "Sorry, I couldn't finish that. I'm passing you to a human agent."
Write it live. Ask what happens if the model never answers: rounds reaches MAX_TOOL_ROUNDS and the customer goes to a person.

Section 4

One Door

Every tool request goes through Toolbox.run.

⌨ toolbox.py — run

    def run(self, name, arguments, history):
        """Check one tool request. Run the tool only if every check passes."""
        if name == "look_up_order":
            order_id = self.clean(arguments, "order_id")
            if order_id == "":
                return "The order ID is missing. Ask the customer for it."
            if not self.customer_said(history, order_id):
                return "The customer has not given that order ID. Ask them for it."
            return self.order_tool.look_up_order(order_id)
        if name == "check_stock":
            item = self.clean(arguments, "item")
            if item == "":
                return "The product is missing. Ask the customer which product."
            return self.stock_tool.check_stock(item)
        if name == "request_address_change":
            order_id = self.clean(arguments, "order_id")
            new_address = self.clean(arguments, "new_address")
            if order_id == "" or new_address == "":
                return "The order ID and the new address are both needed."
            if not self.customer_said(history, order_id):
                return "The customer has not given that order ID. Ask them for it."
            if not self.customer_said(history, new_address):
                return "The customer has not given that address. Ask them for it."
            return self.change_queue.request_address_change(order_id, new_address)
        return f"There is no tool named {name}."
Walk the order: name known? value present? did the customer actually say it? Each refusal is a sentence for the model.

The made-up address

  • Asked I want to change my shipping address with no details, the model made up order A100 and an address and filed it in five out of five runs with the check off.
  • With the check on, it was refused in five out of five runs, and the model asked the customer.
  • "" in "any text" is True: the empty check comes first.

Changes Wait for a Person

A change tool files a request. Only approve changes an order.

⌨ Try the queue

from change_queue import ChangeQueue
from order_tool import OrderLookup

orders = {"A100": {"status": "shipped", "address": "14 Bay Road"}}
queue = ChangeQueue(OrderLookup(orders))

print(queue.request_address_change("A100", "9 Pine Street"))
print(orders["A100"]["address"])
print(queue.approve(1))
print(orders["A100"]["address"])
print(queue.approve(1))

# Output:
# Request 1 was sent to staff. The address has not changed yet.
# 14 Bay Road
# Request 1 approved.
# 9 Pine Street
# Request 1 is already approved.
The address stays 14 Bay Road until approve. A second approve changes nothing.

What Tools Did Not Fix

Close the loop on the three problems.

Fixed, not fixed, kept on purpose

  • Fixed: A101 answered from a lookup in five out of five runs.
  • Not fixed: the false closing time, repeated in five out of five runs. No tool knows the hours.
  • Kept: gift cards still go to a person. A protective rule should prefer false alarms.
Answer the opening promise: matching only the whole word would miss 'Can I pay by card?'. A wait is cheap; a missed payment question is not.

Essential, optional, left out

  • Essential: tool calls and docstrings, decide, the loop and its limit, the Toolbox checks, the change queue, FakeModel tests.
  • Optional: tool_messages, the fallback model, turning a guardrail off to watch.
  • Left out: several tool calls at once, streaming, online services, signing customers in, lasting data.
