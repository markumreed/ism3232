From rules to repository in six moves

Every example on this page comes from one small business, so you can watch a whole project come together.

The running example · Lakeshore Kayak Tours

Lakeshore Kayak Tours prices each booking by the seat. Its five rules:

  1. The tour cost is the seat price times the number of seats.
  2. The discount depends on the number of seats: fewer than 6 seats, no discount; 6 through 19 seats, 10%; 20 seats or more, 25%.
  3. The 25% discount is only for school groups. Any other booking of 20 seats or more gets the 10% discount.
  4. A $30 launch fee is added when the discounted cost is below $200.
  5. A booking total of $1,000 or more needs a second guide.

Work in this order. Each move ends with something that runs.

  1. Mark up the rules. Circle every number, because each one becomes a named constant. Underline every boundary word, such as "fewer than", "or more", and "below". Box the sentence that mentions a True/False input.
  2. Build the skeleton and commit it. Folder, virtual environment, pytest and ruff, the seven files, a public repository. Make your first commit before any logic exists.
  3. Write one function, then its tests, then commit. Do not write five functions and then fifteen tests. A function is finished when its tests pass.
  4. Write main.py last. It only imports, loops, and prints. Compare its output with the brief one line at a time.
  5. Run the ritual. ruff format ., then ruff check ., then pytest -v. Fix and repeat until all three are clean.
  6. Write the README, push, and look. Open the repository in a private browser window and read it the way the grader will.

Functions: rules with a True/False input 30 points

Two inputs decide the discount: how many seats, and whether the group is a school. The sentence that mentions the True/False input is where most of the points are lost.

Bug report 1
A company retreat was billed at the school-group rate

Orbit Robotics booked 40 seats at $30.00 for a company retreat. The invoice came to $900.00. It should have been $1,080.00.

MID_TIER_SEATS = 6
TOP_TIER_SEATS = 20
MID_TIER_RATE = 0.10
TOP_TIER_RATE = 0.25


def get_group_discount(seats: int, school: bool = False) -> float:
    """Return the discount rate as a decimal."""
    if seats >= TOP_TIER_SEATS:
        return TOP_TIER_RATE
    elif seats >= MID_TIER_SEATS:
        return MID_TIER_RATE
    else:
        return 0.0


print(get_group_discount(40))    # prints 0.25

Find the bug before you open the answer.

Reveal the bug

Rule 3 says the 25% discount is only for school groups. The function takes a school parameter and never reads it, so every booking of 20 seats or more gets the top rate. "Only for" adds a second condition to the top tier, joined with and.

FixRead every parameter the rule mentions

The top tier now needs two things to be true: 20 seats or more and a school group. A company with 40 seats fails that test and falls through to the next one.

def get_group_discount(seats: int, school: bool = False) -> float:
    """Return the discount rate as a decimal."""
    if seats >= TOP_TIER_SEATS and school:
        return TOP_TIER_RATE
    elif seats >= MID_TIER_SEATS:
        return MID_TIER_RATE
    else:
        return 0.0

Four calls check four different paths through the function:

print(get_group_discount(5))                  # below the first tier
print(get_group_discount(6))                  # the first tier starts here
print(get_group_discount(20))                 # 20 seats, not a school
print(get_group_discount(20, school=True))    # 20 seats, a school

Three wordings, three shapes

A True/False input can bend a tiered rule in more than one way. Read the sentence for which of these it is saying.

The rule saysWhat it meansShape in code
"The 25% discount is only for school groups."The top tier needs both conditionsif seats >= TOP_TIER_SEATS and school:
"School groups always get at least the 10% discount, even on bookings of fewer than 6 seats."The flag opens the middle tier by itselfelif seats >= MID_TIER_SEATS or school:
"School groups get an extra 5 percentage points, but only on bookings of 6 seats or more."Find the tier first, then add to itStore the tier's rate in a variable. After the chain, a separate if with both conditions adds the extra

In the second wording the top tier is still checked first, so a school with 20 seats gets the top rate, not the middle one. In the third, "5 percentage points" means 10% becomes 15%: you add 0.05 to the rate.

6 or more, at least 6>= 6

One function calls the others

Rule 4 needs the cost and the discount, and both already have a function. The third function calls them. It does not repeat their logic.

LAUNCH_FEE = 30.00
LAUNCH_FEE_LIMIT = 200.00


def calculate_booking_total(
    seat_price: float, seats: int, school: bool = False
) -> float:
    """Return the total for one booking, with the launch fee if it applies."""
    cost = calculate_tour_cost(seat_price, seats)
    rate = get_group_discount(seats, school)
    discounted = cost * (1 - rate)
    if discounted < LAUNCH_FEE_LIMIT:
        return discounted + LAUNCH_FEE
    return discounted

The fee test reads discounted, because the rule says "when the discounted cost is below $200". Testing cost would be a different rule. Calculate the value the sentence names, then test it.

Bug report 2
Four bookings went in. Revenue came back as one

The week's four bookings were totalled for the owner. The report said $130.00, which is exactly what the first booking came to.

bookings = [

    {"group": "Pinecrest Middle", "seat_price": 22.00, "seats": 24, "school": True},

Find the bug before you open the answer.

Reveal the bug

return is indented inside the loop, so the function hands back the total and stops during the first pass. A return ends the function immediately, even in the middle of a loop. It belongs one level out, lined up with for.

FixReturn after the loop

def total_revenue(bookings: list) -> float:
    """Return the sum of the booking totals for every booking in the list."""
    total = 0.0
    for booking in bookings:
        total += calculate_booking_total(
            booking["seat_price"], booking["seats"], booking["school"]
        )
    return total
Output
Total revenue: $1807.60
⚠ Loop only

On the exam, the function that adds up a list must get its total from your own for loop. sum(), max(), min(), sorted(), and comprehensions are not accepted.

Check six things on every function:

  • The name and parameter order match the brief exactly. Your functions are tested by name. A function called get_discount when the brief says get_group_discount fails every test written for it.
  • Every number is a constant. TOP_TIER_SEATS, not a bare 20 typed inside the function.
  • Type hints and a docstring. One line that says what the function returns.
  • return, never print. A function that prints gives its caller None, and every test of it fails.
  • Defaults go last. school: bool = False comes after the parameters that have no default.
  • Rates are decimals. Return 0.10, not 10, so cost * (1 - rate) works.

Tests: both sides of every limit 20 points

A test suite can be completely green and still let a wrong rule through. The instructor's tests check the value exactly at each limit. Yours should get there first.

Bug report 3
Two green tests, and a tour that left one guide short

A sunset charter of 5 seats at $200.00 came to exactly $1,000.00. It went out with one guide. The function had two tests, and both passed.

SECOND_GUIDE_LIMIT = 1000.00


def needs_second_guide(total: float) -> bool:
    """Return True when the booking needs a second guide."""
    return total > SECOND_GUIDE_LIMIT
def test_small_booking_needs_one_guide():
    assert needs_second_guide(400.00) is False


def test_large_booking_needs_second_guide():
    assert needs_second_guide(1500.00) is True
2 passed in 0.00s

Find the bug, and say why neither test caught it, before you open the answer.

Reveal the bug

Rule 5 says $1,000 or more, which is >=. The function uses >. At 400 and at 1500 the two comparisons give the same answer, so tests that far from the limit cannot tell them apart. Only a test at exactly 1000.00 can.

FixTest the limit and its neighbour

Add one test exactly at the limit and one just on the other side of it.

def test_second_guide_at_exactly_1000():
    assert needs_second_guide(1000.00) is True


def test_no_second_guide_one_cent_below_1000():
    assert needs_second_guide(999.99) is False

Run pytest against the buggy function and the new test fails:

What a full-credit test file has

  • At least 10 tests, all passing. Run pytest -v and count the lines that say PASSED.
  • Every function tested at least once. Five functions, so five is the floor.
  • Both sides of at least two different limits. The table above gives you four to choose from.
  • A test where the True/False input changes the answer. Same seats, with and without school=True.
  • A test of the list function that builds its own short list. Do not import the list from main.py.
  • Names that say what is checked. test_no_launch_fee_at_exactly_200, not test_3.
from business_rules import get_group_discount, total_revenue


def test_20_seats_without_school_stays_at_first_tier():
    assert get_group_discount(20) == 0.10


def test_school_gets_top_tier_at_20_seats():
    assert get_group_discount(20, school=True) == 0.25


def test_total_revenue_adds_every_booking():
    bookings = [
        {"group": "A", "seat_price": 25.00, "seats": 4, "school": False},
        {"group": "B", "seat_price": 30.00, "seats": 40, "school": False},
    ]
    assert round(total_revenue(bookings), 2) == 1210.00


def test_total_revenue_of_empty_list_is_zero():
    assert total_revenue([]) == 0

Work out 1210.00 by hand before you trust it: 4 seats at $25.00 is $100.00 with no discount, plus the $30 fee, which is $130.00. 40 seats at $30.00 is $1,200.00 less 10%, which is $1,080.00. The expected value in a test always comes from the rules, never from running your own function.

Money and round()

Floats carry tiny errors: in Python, 0.1 + 0.2 is 0.30000000000000004. When a test compares a money result, round it to 2 places first, the way Lab 7 does: assert round(calculate_booking_total(22.00, 24, school=True), 2) == 396.00.

Break it on purpose

To find out whether your tests are any good, damage your own function and see if they notice.

  1. Change one comparison, such as >= to >, and save.
  2. Run pytest. At least one test should fail.
  3. If everything still passes, you are missing the test at that limit. Write it.
  4. Change the comparison back and run pytest again.

Project: a repository someone else can run 15 points

Your code is graded on another computer. It gets cloned from GitHub, its requirements are installed, and then pytest and python3 main.py are run. Anything that only exists on your laptop does not exist.

Reveal the problems

ruff: two commands, two different jobs 10 points

ruff format and ruff check are both in the ritual because neither one does the other's job.

Bug report 5
ruff format said all clear. ruff check found four problems

This file, report.py, was formatted, and ruff reported nothing to change. Then came the check. Below the code are the last two lines of its report.

import os

The code runs and gives the right answer. Find the four things ruff objects to before you open the answer.

Reveal the four problems
  1. F401: os is imported and never used.
  2. I001: the import block is not sorted. The two names on the from line are out of alphabetical order, and ruff wants the standard-library import in its own group.
  3. F841: label is assigned and never used.
  4. SIM103: the if / else that returns True or False can return the condition directly.

    """Return True when the booking needs a second guide."""
    total = calculate_booking_total(seat_price, seats)
    return needs_second_guide(total)

Mistakes that cost points

Read each one, predict what goes wrong, then open it to check.

Ignoring a parameter the rule mentions

What goes wrong: The True/False input never changes the answer, so one whole rule is missing.

Fix: Every parameter in the signature should be read somewhere in the body.

Reading "only for" as "also for"

What goes wrong: Everyone in the top tier gets the rate meant for one group.

Fix: "Only for" is and. Say the condition out loud and compare it with the sentence.

> where the rule says "or more", or <= where it says "below"

What goes wrong: The value exactly at the limit lands on the wrong side.

Fix: Translate the words, then test the limit and the value next to it.

Testing the original cost when the rule names the discounted cost

What goes wrong: The fee is decided by the wrong number.

Fix: Reread which value the rule names, and calculate it first.

Typing a limit as a bare number inside a function

What goes wrong: The same number appears in several places and they drift apart. It also costs points under Complete submission.

Fix: One constant in capitals at the top of the file, used everywhere.

Returning a percentage (10) where the brief asks for a decimal (0.10)

What goes wrong: cost * (1 - 10) is a large negative number.

Fix: Return the rate as a decimal and let the caller do the multiplication.

print instead of return in a function

What goes wrong: The caller receives None, and every test of the function fails.

Fix: Return the value. Only main.py prints.

return indented inside a loop

What goes wrong: The function stops during the first pass and returns one record's amount.

Fix: Line the final return up with for.

sum() or a comprehension in the list function

What goes wrong: Built-in shortcuts are not accepted on the exam, so the function earns nothing for its tests.

Fix: Set up a total before the loop and add to it inside the loop.

A function name that differs from the brief

What goes wrong: The instructor's tests call your functions by name. A different name fails every test for that function.

Fix: Copy the names and the parameter order from the brief before you write any logic.

Tests that only use comfortable numbers

What goes wrong: Everything passes while a comparison is wrong at the limit.

Fix: For each limit, one test exactly at it and one just beside it.

Changing a test's expected value until it passes

What goes wrong: The test now agrees with the bug.

Fix: Work out the expected value from the rules, by hand. If the test fails, fix the function.

Comparing money with == without rounding

What goes wrong: A correct function fails its test because of a float error in the fifteenth decimal place.

Fix: assert round(result, 2) == 396.00

Leaving out tests/__init__.py

What goes wrong: ModuleNotFoundError: No module named 'business_rules', and no test runs.

Fix: Create the empty file when you create the folder.

Committing .venv/

What goes wrong: Thousands of files that do not work on any other machine, and lost points under Complete submission.

Fix: Write .gitignore before your first git add.

Running ruff format and skipping ruff check

What goes wrong: The layout is perfect and the unused import is still there.

Fix: All three ritual commands, every time, in order.

Committing everything at the end

What goes wrong: One commit shows no stages, so the history earns nothing.

Fix: Commit each time a part passes the ritual.

Forgetting to push, or leaving the repository private

What goes wrong: The grader sees an old version, or nothing.

Fix: Open your URL in a private browser window before you submit it.

Practice project: Stitchline Uniforms

This project has the same six parts as the exam, with a different business and different numbers. Build it from an empty folder to a pushed repository. Use your notes, your labs, and the course site, and nothing else, exactly as you will on the exam.

The business and its rules

Stitchline Uniforms prints team shirts and prices each order by the shirt.

  1. The shirt cost is the price per shirt times the number of shirts.
  2. The discount depends on the number of shirts: fewer than 12 shirts, no discount; 12 through 47 shirts, 5%; 48 shirts or more, 10%.
  3. Schools get an extra 3 percentage points of discount, but only on orders of 12 shirts or more. For them, 5% becomes 8% and 10% becomes 13%.
  4. A $20 artwork fee is added when the discounted cost is below $100.
  5. An order total of $750 or more needs the owner's approval.
