Python talks to SQLite

Python comes with a module for SQLite called sqlite3. Every database function follows the same pattern: open a connection, run SQL, close the connection. Bayside wraps the pattern in three helpers. Here is the first:

database.py
def query_all(db_file, sql, values=()):
    """Run a SELECT and return every row as a dictionary."""
    conn = sqlite3.connect(db_file)
    conn.row_factory = sqlite3.Row
    rows = conn.execute(sql, values).fetchall()
    conn.close()
    return [dict(row) for row in rows]
  • sqlite3.connect(db_file) opens the database file, or creates it if it is not there.
  • row_factory = sqlite3.Row lets each row be looked up by column name.
  • execute(sql, values) runs the SQL. Each ? in the SQL is filled from values, which is a tuple: a list that cannot be changed, written with round brackets. A tuple with one item needs a comma: (0,). Without it, (0) is just the number 0.
  • fetchall() returns every row, and close() closes the connection.
  • [dict(row) for row in rows] turns each row into an ordinary dictionary, the kind you have used since Week 6.

This is what the helpers return in a real Python shell:

Python shell

The other two helpers build on the same pattern:

database.py
def query_one(db_file, sql, values=()):
    """Run a SELECT and return the first row as a dictionary, or None."""
    rows = query_all(db_file, sql, values)
    if rows == []:
        return None
    return rows[0]
database.py
def change(db_file, sql, values=()):
    """Run an INSERT or UPDATE, save it, and return the ID of the last row inserted."""
    conn = sqlite3.connect(db_file)
    cursor = conn.execute(sql, values)
    conn.commit()
    row_id = cursor.lastrowid
    conn.close()
    return row_id
  • commit() saves the change. Nothing an INSERT or UPDATE does is kept until it runs.
  • lastrowid is the number SQLite gave the row just inserted, which is how a new change request learns its number.

The business functions

Each business function is one short call to a helper. Lookups need the exact ID: A1000 and a100 are not A100.

database.py
def find_order(db_file, order_id):
    """Return one order, or None if there is no order with exactly this ID."""
    return query_one(db_file, "SELECT * FROM orders WHERE order_id = ?", (order_id,))
database.py
def product_names(db_file):
    """Return the name of every product."""
    rows = query_all(db_file, "SELECT name FROM products ORDER BY name")
    return [row["name"] for row in rows]
database.py
def find_product(db_file, name):
    """Return one product, or None if there is no product with this name."""
    return query_one(db_file, "SELECT * FROM products WHERE name = ?", (name,))

Three functions file a change request, find one, and list the ones waiting:

database.py
def add_change_request(db_file, order_id, new_address):
    """File a new address change. It waits for staff. Return its number."""
    sql = "INSERT INTO change_requests (order_id, new_address) VALUES (?, ?)"
    return change(db_file, sql, (order_id, new_address))
database.py
def find_request(db_file, number):
    """Return one change request, or None if there is no request with this number."""
    return query_one(
        db_file, "SELECT * FROM change_requests WHERE number = ?", (number,)
    )
database.py
def waiting_requests(db_file):
    """Return the requests still waiting for staff, oldest first."""
    sql = "SELECT * FROM change_requests WHERE status = 'waiting' ORDER BY number"
    return query_all(db_file, sql)
database.py
def approve_request(db_file, number):
    """Approve one waiting request: change the order's address and mark it approved."""
    request = find_request(db_file, number)
    if request is None:
        return f"There is no request {number}."
    if request["status"] != "waiting":
        return f"Request {number} is already {request['status']}."
    conn = sqlite3.connect(db_file)
    conn.execute(
        "UPDATE orders SET address = ? WHERE order_id = ?",
        (request["new_address"], request["order_id"]),
    )
    conn.execute(
        "UPDATE change_requests SET status = 'approved' WHERE number = ?", (number,)
    )
    conn.commit()
    conn.close()
    return f"Request {number} approved."

database.py
def reject_request(db_file, number):
    """Reject one waiting request. The order does not change."""
    request = find_request(db_file, number)
    if request is None:
        return f"There is no request {number}."
    if request["status"] != "waiting":
        return f"Request {number} is already {request['status']}."
    sql = "UPDATE change_requests SET status = 'rejected' WHERE number = ?"
    change(db_file, sql, (number,))
    return f"Request {number} rejected."

One more function builds the tables. It reads schema.sql with with open(...) as f:, the same with you used in Week 6 to write a file, and runs the whole file with executescript:

database.py
def create_tables(db_file):
    """Create the tables and the sample rows, unless they are already there."""
    with open("schema.sql") as f:
        script = f.read()
    conn = sqlite3.connect(db_file)
    conn.executescript(script)
    conn.commit()
    conn.close()

The app calls create_tables every time it starts. Week 13’s IF NOT EXISTS and INSERT OR IGNORE are what make that safe. Three more functions in the file, reset_database, restock and status_report, are for Week 15’s Staff tab.

Placeholders

A placeholder sends a value separately from the SQL, so the value can only ever be data. Building SQL with an f-string puts the value inside the SQL. Here the same text goes through both:

placeholders.py
import sqlite3

from database import create_tables, find_order

create_tables("bayside.db")
order_id = "A100' OR '1'='1"
conn = sqlite3.connect("bayside.db")
sql = f"SELECT * FROM orders WHERE order_id = '{order_id}'"
rows = conn.execute(sql).fetchall()
conn.close()
print(len(rows), "orders from the f-string query")
print(find_order("bayside.db", order_id), "from find_order")
Output
6 orders from the f-string query
None from find_order
Why this matters more in an agent

The f-string query returned every order; the placeholder query found none. In a form app a person types the value. In an agent the model writes it, and a customer can steer the model. A placeholder keeps whatever arrives as plain text.

Testing with tmp_path

Tests must never touch the real database. pytest gives any test that asks for tmp_path a new, empty folder that only it uses, and tmp_path / "test.db" is a file path inside that folder:

tests/test_database.py
import database


def make_db(tmp_path):
    """Create a fresh database with the sample rows, in a folder only this test uses."""
    db_file = tmp_path / "test.db"
    database.create_tables(db_file)
    return db_file

tools.py

The tools class is handed the database file and keeps Week 12’s two methods. Each tool method calls a database function:

tools.py
    def __init__(self, db_file):
        """Remember which database the tools read and write."""
        self.db_file = db_file
tools.py
    def look_up_order(self, order_id):
        """Look up the status of one order.

        Args:
            order_id: The order ID, like A100.
        """
        for word in order_id.upper().split():
            order = database.find_order(self.db_file, word.strip("?.!,"))
            if order is not None:
                return f"Order {order['order_id']} is {order['status']}."
        return "No order with that ID was found. Order IDs look like A100."
tools.py
    def request_address_change(self, order_id, new_address):
        """Ask staff to change the shipping address on one order. Staff must approve it.

        Args:
            order_id: The order ID, like A100.
            new_address: The full new shipping address.
        """
        order_id = order_id.upper()
        if database.find_order(self.db_file, order_id) is None:
            return "No order with that ID was found. Order IDs look like A100."
        number = database.add_change_request(self.db_file, order_id, new_address)
        return f"Request {number} was sent to staff. The address has not changed yet."

A change tool only files a request; nothing about the order changes until staff approve. The door is Week 12’s, with one new tool, check_request, so a customer can ask what staff decided:

tools.py
    def run(self, name, arguments, history):
        """Check one tool request. Run the tool only if every check passes."""
        if name == "look_up_order":
            order_id = self.clean(arguments, "order_id")
            if order_id == "":
                return "The order ID is missing. Ask the customer for it."
            if not self.customer_said(history, order_id):
                return "The customer has not given that order ID. Ask them for it."
            return self.look_up_order(order_id)
        if name == "check_stock":
            item = self.clean(arguments, "item")
            if item == "":
                return "The product is missing. Ask the customer which product."
            return self.check_stock(item)
        if name == "request_address_change":
            order_id = self.clean(arguments, "order_id")
            new_address = self.clean(arguments, "new_address")
            if order_id == "" or new_address == "":
                return "The order ID and the new address are both needed."
            if not self.customer_said(history, order_id):
                return "The customer has not given that order ID. Ask them for it."
            if not self.customer_said(history, new_address):
                return "The customer has not given that address. Ask them for it."
            return self.request_address_change(order_id, new_address)
        if name == "check_request":
            number = self.clean(arguments, "number")
            if number == "":
                return "The request number is missing. Ask the customer for it."
            if not self.customer_said(history, number):
                return (
                    "The customer has not given that request number. Ask them for it."
                )
            return self.check_request(number)
        return f"There is no tool named {name}."
tools.py
    def words(self, text):
        """Return text in lower case as whole words, without ?.!,# around each word."""
        cleaned = []
        for word in text.lower().split():
            cleaned.append(word.strip("?.!,#"))
        return " " + " ".join(cleaned) + " "
tools.py
    def customer_said(self, history, text):
        """Return True if the customer typed text as whole words."""
        wanted = self.words(text)
        for message in history:
            if message["role"] == "user" and wanted in self.words(message["content"]):
                return True
        return False

In Week 12, customer_said checked whether the text appeared anywhere in a customer message. So when a customer typed A1000 and the model asked for A100, the check passed, because A100 is inside A1000. An automated security review of this app found it, and the fix came test-first: test_a_typo_order_id_does_not_count_as_typed failed, then words made it pass. words uses two string methods you have not met: .split() breaks text into a list of words, and " ".join(...) puts a list of words back together with spaces.

    def decide(self, instructions, history, tools):
        """Send the conversation and the tools. Return a reply or a tool request."""
        messages = [{"role": "system", "content": instructions}]
        for message in history[-MAX_MESSAGES:]:
            if message["role"] == "tool":
                messages = messages + self.tool_messages(message)
            else:
                messages.append(message)
        try:
            response = chat(model=self.model_name, messages=messages, tools=tools)
        except ConnectionError:
            return None
        except ResponseError:
            return None
        if response.message.tool_calls:
            call = response.message.tool_calls[0]
            return {"tool": call.function.name, "arguments": call.function.arguments}
        return {"text": response.message.content}

What this module leaves out, and why

  • JOINs. Each question your capstone answers comes from one table.
  • The with sqlite3.connect(...) shortcut. It saves changes but does not close the connection, so this course opens and closes connections itself.
  • ORMs and migrations. Tools that write the SQL for you, and tools that change a schema over time, are more than a one-file SQLite app needs.
  • Two people using the app at once. That comes with the Staff tab in Week 15.

Module Quiz

Q1 · Multiple Choice
Which line keeps a customer’s text from being run as SQL?
  • a) conn.execute("SELECT * FROM orders WHERE order_id = ?", (order_id,))
  • b) conn.execute(f"SELECT * FROM orders WHERE order_id = '{order_id}'")
  • c) conn.execute("SELECT * FROM orders WHERE order_id = '" + order_id + "'")
  • d) conn.execute("SELECT * FROM orders WHERE order_id = %s" % order_id)
Answer
conn.execute("SELECT * FROM orders WHERE order_id = ?", (order_id,)) — The ? placeholder sends the value separately, so it can only ever be data.
Q2 · True / False
(order_id) is a tuple with one item.
Answer
False — It is order_id in brackets. A one-item tuple needs a comma: (order_id,).
Q3 · Code Trace
What does this return?
query_one(db_file, "SELECT * FROM orders WHERE order_id = ?", ("A999",))
Answer
None — query_one returns None when no row matches.
Q4 · Multiple Choice
What happens if change leaves out conn.commit()?
  • a) The change is lost when the connection closes
  • b) SQLite saves it anyway
  • c) Python raises an error
  • d) Only the first change is saved
Answer
The change is lost when the connection closes — Nothing is saved until commit.
Q5 · True / False
A test that uses tmp_path gets its own new folder, so it never touches bayside.db.
Answer
True — Each test gets a folder only it uses.
Q6 · Multiple Choice
Why does Week 14 match whole words in customer_said?
  • a) So A100 does not count when the customer typed A1000
  • b) So the check runs faster
  • c) Because SQLite needs whole words
  • d) So capital letters matter
Answer
So A100 does not count when the customer typed A1000 — Week 12’s check let A100 match inside A1000.
Q7 · Code Trace
What does words return for this text?
tools.words("Where is #A100?")
Answer
" where is a100 " — lower case, ?.!,# stripped from each word, and a space at each end.
Q8 · Multiple Choice
What did agent.py change to work with the database?
  • a) Only its first line
  • b) Its tool loop
  • c) Its history format
  • d) Every method that reads orders

Q9 · True / False
Calling approve_request twice on the same request changes the address twice.
Answer
False — The second call finds the request already approved and changes nothing.
Q10 · Short Answer
Why do placeholders matter more in an agent than in a form?
Answer
In a form a person types the value. In an agent the model writes it, and a customer can steer what the model writes. A placeholder keeps whatever arrives as plain text, never as SQL.
