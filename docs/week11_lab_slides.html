Part 2 · 0:17–0:27

First Call from Python

Teaching goal: a list of messages goes in, a reply comes out, and the reply can be invented.

A list of messages, three roles

Concept

system — your instructions to the model. The customer never sees them.

user — something the customer typed.

assistant — something the model replied earlier.

Each message is a dictionary with a role and a content: the shape of the history you have kept since Week 10.

Students have been building this exact list for a week with no model on the other end.

Build the list by hand

instructions = "You are Sunny. Answer in one short sentence." history = [ {"role": "user", "content": "hello"}, {"role": "assistant", "content": "Hello! How can I help you today?"}, {"role": "user", "content": "What are your store hours?"}, ] messages = [{"role": "system", "content": instructions}] messages = messages + history for message in messages: print(message["role"], "-", message["content"]) print(len(messages))

No model here. This block only builds the list a model would be sent. messages + history joins two lists. Press Run.

messages = messages + history is new: + joins two lists into one. The instructions go first, then the conversation.

Expected output

system - You are Sunny. Answer in one short sentence.
user - hello
assistant - Hello! How can I help you today?
user - What are your store hours?
4

Four messages: one system, then the three from the history.

Ask which of the four the customer never saw. The first.

first_chat.py — run on your own machine

# first_chat.py # Author: [Your Name] from ollama import chat MODEL_NAME = "granite4.1:3b" INSTRUCTIONS = """You are Sunny, a support assistant for Bayside Outfitters. Answer in one short sentence.""" messages = [ {"role": "system", "content": INSTRUCTIONS}, {"role": "user", "content": "What are your store hours?"}, ] response = chat(model=MODEL_NAME, messages=messages) print(response.message.content)

The Model Has No Memory

Teaching goal: each call starts from nothing, so the program must resend the conversation.

no_memory.py — two separate calls

# no_memory.py # Author: [Your Name] from ollama import chat MODEL_NAME = "granite4.1:3b" INSTRUCTIONS = """You are Sunny, a support assistant for Bayside Outfitters. Answer in one short sentence.""" first = [ {"role": "system", "content": INSTRUCTIONS}, {"role": "user", "content": "Hello, my name is Dana."}, ] response = chat(model=MODEL_NAME, messages=first) print(response.message.content) second = [ {"role": "system", "content": INSTRUCTIONS}, {"role": "user", "content": "What is my name?"}, ] response = chat(model=MODEL_NAME, messages=second) print(response.message.content)

Needs Ollama. Two calls, each with its own short list.

The second list does not contain the first message.

One real run

Hello Dana, how may I assist you today?
Your name is not provided in the given context.

The second call knows nothing about the first.

Some runs produce a confidently wrong name. Either way the point holds: the model was never sent it.

with_memory.py — one growing list

# with_memory.py # Author: [Your Name] from ollama import chat MODEL_NAME = "granite4.1:3b" INSTRUCTIONS = """You are Sunny, a support assistant for Bayside Outfitters. Answer in one short sentence.""" messages = [{"role": "system", "content": INSTRUCTIONS}] messages.append({"role": "user", "content": "Hello, my name is Dana."}) response = chat(model=MODEL_NAME, messages=messages) print(response.message.content) messages.append({"role": "assistant", "content": response.message.content}) messages.append({"role": "user", "content": "What is my name?"}) response = chat(model=MODEL_NAME, messages=messages) print(response.message.content) messages.append({"role": "assistant", "content": response.message.content}) print(len(messages))

Needs Ollama. Append the message, call the model, append the reply, repeat.

Every call sends the whole list. The model is not remembering. The program is.

One real run

Your name is Dana.
5

Now it answers, because the message with the name was sent again. Five messages in the list.

A Mock Model, Handed to the Chatbot

Teaching goal: the model is a part with one method. Build the stand-in first so the chatbot and its tests work on any computer. Say to the class: "Close Ollama if you like. Nothing in the next fifteen minutes needs it."

The model is a part with one method

Concept

A model object has one method: reply(instructions, history). It returns the text of a reply.

MockModel gives fixed replies and needs nothing installed.

OllamaModel asks the real model.

They are unrelated classes that agree on one method name, so the chatbot can be handed either. No inheritance is involved.

This is composition a second time. The chatbot already holds two tools. Now it holds a model.

Live-code — mock_model.py

class MockModel: """A stand-in for an AI model. It gives the same simple replies every time.""" def reply(self, instructions, history): last_message = history[-1]["content"].lower() if "hello" in last_message: return "Hello! How can I help you today?" return "I'm not sure how to help with that. I can check an order or stock." model = MockModel() history = [{"role": "user", "content": "Hello there"}] print(model.reply("Be friendly.", history)) history = [{"role": "user", "content": "Do you price match?"}] print(model.reply("Be friendly.", history))

The class matches the lab page. The lines below it call reply twice. Press Run.

No __init__: the class has nothing to remember. history[-1] is the last item in the list.

Hello! How can I help you today?

The same two replies every time. That is what makes it usable in a test.

Part 5 · 0:50–1:05

The Real Model, with a Safety Net

Teaching goal: introduce try and except, then use them so a failed model returns None and the conversation carries on.

An error you already know

orders = {"A100": "shipped"} print(orders["A999"]) print("The program keeps running.")

Week 8's KeyError. Press Run and notice which line never prints.

The second print never runs. An unhandled error stops the program where it happens.

What it raises

Traceback (most recent call last):
  ...
KeyError: 'A999'

The program stopped at the error. The program keeps running. was never printed.

In the browser the file name and line number differ from a real run. The error type and message are what matter.

try and except

orders = {"A100": "shipped"} try: print(orders["A999"]) except KeyError: print("No such order.") print("The program keeps running.")

The same lookup inside a try. Press Run.

try: starts code that might fail. except KeyError: names one error and says what to do if it happens. If no error happens, the except block is skipped. Name the error you expect. An except that catches everything also hides typos.

Expected output

No such order.
The program keeps running.

The error was handled, and the last line ran.

try does not fix the cause. It decides what happens next.

ollama_model.py — run on your own machine

# ollama_model.py # Author: [Your Name] from ollama import ResponseError, chat class OllamaModel: """A real AI model that runs on this computer through Ollama.""" def __init__(self, model_name): """Remember which model to ask.""" self.model_name = model_name def reply(self, instructions, history): """Send the instructions and the conversation to the model. Return its reply.""" messages = [{"role": "system", "content": instructions}] messages = messages + history try: response = chat(model=self.model_name, messages=messages) except ConnectionError: return None except ResponseError: return None return response.message.content

The same pattern with two errors. ConnectionError: Ollama is not running. ResponseError: Ollama answered with an error, such as a model that was never downloaded.

Both return None, the signal the tools give when they have no answer. The chatbot decides the wording. Only this file imports ollama.

What stays in code

Facts that matter come from a tool or from data: order status, stock, prices.
