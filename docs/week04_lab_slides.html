The idea — three tools, three questions

Concept

rg 'text' — searches the contents of every file for that text, printing each matching line with its filename and line number. Respects .gitignore by default, so it never wastes time inside .venv/.

find . -name '*.py' — searches for files by name pattern, not by contents. . means "starting here"; * is a wildcard. It cannot tell you what is inside a file.

tree -L 3 — draws the folder structure as a text diagram, depth-limited to 3 levels. The fastest way to get oriented in an unfamiliar project.

The core distinction to drill: rg answers "which lines / files contain this text"; find answers "which files are named like this"; tree answers "what shape is this project." rg 'def ' with a trailing space matches function definitions, not every occurrence of the substring def — a concrete illustration that a pattern's exact text matters. rg -l switches output to just the filenames that contain a match.

The idea — test_ naming + assert

Concept

pytest automatically discovers any function whose name starts with test_ — a naming convention, not a decorator. That is why the filename (test_week4.py) and every function in it are prefixed test_.

assert EXPR is new syntax today: it checks that EXPR is True. If it isn't, the test is marked failed; if it holds, nothing visible happens — the test passes silently. That is the entire mechanism of automated testing.

path.split('/') breaks a path string into a list of its segments at every /; 'ism3232' in parts checks whether that exact string appears anywhere in the resulting list.

mkdir -p tests — -p means "don't error if it already exists, and create any needed parents" — safe and idempotent. touch tests/__init__.py tests/test_week4.py — two files at once; __init__.py, even empty, marks tests/ as a proper Python package, which helps pytest's discovery. test_string_is_lowercase: 'ism3232' == 'ism3232'.lower() holds because the string is already lowercase. If name were 'ISM3232' the assertion would be 'ISM3232' == 'ism3232', which is False — the test would fail. (The guide's L178 parenthetical says "it would still pass"; that is imprecise — name == name.lower() holds only when name is already lowercase. Slide 28's predict and aside carry the same correction.)

1. Confirm (pwd, tree -L 3) → 2. Activate (source .venv/bin/activate) → 3. Format then Lint (ruff format ., ruff check .) → 4. Test (pytest) → 5. Stage / Commit / Push (git status, git add ., git commit -m '...', git push).

ruff format . actually rewrites files on disk; ruff check . only reports. Format first, so lint runs against already-clean formatting. pytest here runs without -v — a fast pass/fail gate, not a detailed report.

The commit message matters: 'lab 4: search ritual and git' is specific and descriptive; 'final' or 'update' are not, and this course's grading looks at commit-message quality directly.

Each step is a gate the next one assumes has already passed. Running the steps out of order — most commonly committing/pushing before running ruff/pytest — means a broken or unformatted submission goes out before it is verified. git push uploads the commit to GitHub; Part 4 sets up exactly where it goes for the very first time.

The idea — connect local to remote, once

Concept

git remote add origin https://github.com/YOURUSERNAME/ism3232-module02.git — tells your local repo about a remote location (origin is just a conventional name). Up to now git commit has only made local history; this line gives git push an actual destination.

git branch -M main — renames the current branch to main (the modern default), -M forcing the rename.

git push -u origin main — pushes main to origin; -u (--set-upstream) links this local branch to that remote branch permanently, so every future push can just be git push alone. This is a one-time setup step precisely because of -u.

Create the GitHub repo as Private with no README — if GitHub auto-creates a README and the local repo also has its own initial commit, the two histories diverge and the first git push fails with a conflict. Without -u on this first push, every future push would need origin main spelled out again.
